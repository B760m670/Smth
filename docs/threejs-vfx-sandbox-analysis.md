# Elemental Sandbox — разбор исходников

Технический разбор опенсорсной VFX-песочницы на Three.js: шесть настраиваемых
абилок, вся графика генерируется на лету, ни одного спрайта и ни одного
запечённого меша.

**Репозиторий:** `achrefelouafi/LinearAbiltyCastingThreeJS`
(последний коммит на момент разбора — `f9ba4f9`, 2026-08-09).
**Стек:** Three.js `^0.185.1`, Vite `^8.1.5`, lil-gui `^0.21.0`. Больше зависимостей нет.

Разбор сделан по склонированному репозиторию: прочитаны README (589 строк),
`src/archive/README.md` и весь живой исходник; проект собран локально
(`npx vite build` → 84 модуля, 1.11 MB бандла, 1.07 s), чтобы проверить, что
описанное в документации соответствует тому, что действительно компилируется.

---

## 1. Что это, в двух абзацах

Это не библиотека частиц и не демка одного эффекта. Это **стенд для авторинга
VFX**: шесть заклинаний в стиле MOBA-скиллшотов, каждое разложено на сотню-другую
живых слайдеров, и — главное — слайдеры продолжают работать, когда симуляция
поставлена на паузу клавишей `P`. Замораживаешь кадр в середине извержения и
правишь силуэт, палитру и тайминги по неподвижной картинке.

Вся визуальная часть синтезируется в рантайме. Из бинарных ассетов на диске
лежат только персонаж (4 FBX от Mixamo + его diffuse-карта), HDR-проба для IBL и
опциональный набор камня для пола (`floorTexture: false` по умолчанию — пол
шейдерный). Кристаллы, астероид, молния, луч, клетка ловушки, стрелка
прицеливания, ожоги, иней и трещины — процедурная геометрия и GLSL.

## 2. Шесть абилок: README отстаёт от кода

Это первое расхождение, на которое стоит обратить внимание. README открывается
фразой «Five abilities», описывает пять и в таблице управления перечисляет пять
клавиш. В коде их **шесть** — шестая, `GlacierAbility`, уже полностью
интегрирована: зарегистрирована в `AbilityManager`, есть в `ELEMENTS`,
`ELEMENT_META`, в редакторе (`_buildGlacier`) и на клавише `X` / `6` в
`InputManager`. README упоминает её вскользь дважды (в таблице ассетов и в
описании `castAnim`), но раздела у неё нет.

| # | Клавиша | id | Название | Прицел | Ядро реализации |
|---|---------|-----|----------|--------|-----------------|
| 1 | `Q` / `1` | `ice` | Frost Lance | линия | 3 × `InstancedMesh` процедурных кристаллов + патченный `MeshStandardMaterial` |
| 2 | `E` / `2` | `thunder` | Storm Lance | линия | лента-лесенка в parameter space, весь путь — в вершинном шейдере |
| 3 | `R` / `3` | `meteor` | Cinder Fall | линия | икосфера с плоскостными срезами + рейтмарш чёрного тела в proxy-hull |
| 4 | `F` / `4` | `beam` | Nova Beam | линия | параметрическая труба, отрисованная трижды на трёх радиусах |
| 5 | `V` / `5` | `snare` | Voltaic Snare | круг | одна инстансированная лента, четыре роли решаются в вершинном шейдере |
| 6 | `X` / `6` | `glacier` | Glacial Crown | круг | процедурные кристаллы + собственный дисперсионный материал, фронт заморозки и шаттер в шейдере |

Две последние — **far cast**: вместо стрелки рисуется круг с намеренно толстой
границей, который следует за курсором. Со стороны прицеливания far cast — это
line cast, у которого важен только дальний конец, поэтому `Ability`,
`AbilityManager` и `App` не знают о разнице вообще: обе формы заканчиваются одним
событием `cast(origin, direction, distance)`, а зональная абилка читает свою
точку как `pointAt(1)`.

Чтобы сделать абилку зональной, нужно ровно две вещи: `cast: CastShape.ZONE` в
`ELEMENT_META` и `zoneRadius` в её блоке настроек. Индикатор, кольцо дальности,
snap-out и весь цикл прицеливания приходят бесплатно.

## 3. Архитектура: settings — это API

```
src/
  abilities/      база (движущийся фронт) + 6 абилок + пул
  animation/      FBX-персонаж, AnimationMixer, клипы каста, процедурный выпад
  assets/         процедурная геометрия: кристалл, астероид, лента, труба, кольца
  config/         settings.js — единственный источник правды
  core/           App, Renderer, CameraRig, Time, Layers, общие uniform-ы кадра
  effects/        стрелка, круг, декали, трещины, вспышки, пул света, тряска
  input/          InputManager (события) и AimController (обе формы прицела)
  loaders/        AssetLoader с общим LoadingManager
  materials/      Ice, Lightning, Meteor, VolumetricFire, Beam, Snare, Glacier, FrostField
  particles/      GPU-частицы + движок и rate-эмиттеры
  postprocessing/ композер, grade, distortion
  shaders/lib/    общий GLSL: шум и хелперы
  ui/             HUD, lil-gui редактор, пресеты
  utils/          математика, кэш цветов, пул, dispose, патч шейдеров
  world/          окружение, пол, пыль, контактные тени
  archive/        прошлая инкарнация проекта (не импортируется, не бандлится)
```

Живой код — **21 351 строка**, из них ~3 400 строк GLSL в размеченных
`/* glsl */` литералах (плюс несколько сотен строк, инжектируемых в штатные
материалы three без разметки). Архив — ещё 7 115 строк.

Центральная идея: `config/settings.js` держит все значения, и **ни один
подсистемный объект не владеет этим состоянием** — шейдеры, частицы, свет и
пост-обработка каждый кадр *читают* эти объекты. Отсюда редактор без
пересборки: сдвиг слайдера меняет уже стоящее ледяное поле, следующий каст,
окружение и пост-стек одновременно.

```js
import { settings } from './config/settings.js';
settings.ice.height = 7;          // видно на следующем кадре, даже посреди каста
settings.thunder.jitter = 1.2;    // перегибает молнию, которая уже в воздухе
settings.global.timeScale = 0.1;  // замедляет весь каст
```

Пресеты грузятся через `applySettings` — рекурсивный merge **внутрь** тех же
объектов, а не замена. Идентичность объектов сохраняется, поэтому все живые
привязки (uniform-боксы, ссылки внутри частиц) остаются валидными и пресет можно
переключить посреди каста.

Общие для всех абилок сервисы `App` собирает один раз и передаёт в
`AbilityManager` контекстом: `{ scene, camera, environment, particles, lights,
decals, fissures, bursts, shake, flash }`. Проводка строго однонаправленная —
`App` строит системы и упорядочивает обновления, ни одна подсистема не тянется
обратно в `App`.

## 4. Правило, ради которого всё это построено

Формулировка из кода: система может только *сэмплировать* настройки; она не
имеет права скопировать значение в запись при спавне и прочитать его позже.

`IceAbility` держит пул из 288 записей о шипах, и в записи лежат **только
результаты бросков костей**: доля вдоль линии, знаковая доля поперёк, пара
безразмерных джиттеров, `yaw`, флаг «щебень». Ни одного метра, радиана или
секунды. Все размерности разрешаются против `settings.ice` внутри апдейта,
который выполняется и на кадре нулевой длины:

```js
_spikeHeight(record, c, g) {
  let h = lerp(c.heightNear, c.height, Math.pow(saturate(record.along), c.heightCurve));
  h *= 1 + (c.peak - 1) * smoothstep(1 - c.peakWidth, 1, record.along);   // вздутие у точки удара
  ...
}
```

Поэтому `height` перерастит уже стоящее поле, `lean` — перенаклонит его,
`clumping` — переуплотнит к осевой линии. Единственное, что запись всё-таки
захватывает, — **таймстемпы** (момент, когда сработало её собственное
извержение). Это события, а не размерности, и именно поэтому им можно.

Четыре *формообразующих* контрола (`facets`, `taper`, `roughness`, `bend`) в
per-instance трансформацию не выражаются, поэтому они запекаются в геометрию.
`_syncGeometry()` хэширует эти четыре значения и полностью перестраивает три
меша кристаллов при изменении хэша: шестигранный кристалл — 60 треугольников,
дешевле перегенерировать, чем аппроксимировать в шейдере.

`ThunderAbility`, `BeamAbility` и `SnareAbility` доводят правило до предела: у
них **вообще нет объекта пути**. Каст захватывает ровно одно число — `_seed`,
чтобы два каста не нарисовали одинаковую молнию, — а весь путь строится в
вершинном шейдере из живых настроек каждый кадр.

## 5. Мировые координаты в вершинных шейдерах

Это самая интересная часть проекта и то, что отличает его от обычных
particle-демок. Четыре меша построены в **parameter space**: их вершины не
содержат ни одного метра.

### 5.1 Лента молнии — `(t, side)`

`createBoltRibbonGeometry(nodes = 72, strands = 24)` создаёт плоскую лесенку
квадов, где `position = (t, ±1, 0)`. Один инстанс — одна нить. Всё остальное
делает `LightningMaterial`:

```glsl
vec3 boltPoint(float t, float seed, float radial, vec3 n1, vec3 n2, float span) {
  vec3 axis = mix(uOrigin, uTarget, t);
  axis.y += uSag * sin(t * PI);                       // 1. ось, прогнутая провисанием
  float pinch = max(uPinch, 1e-3);
  float ends = smoothstep(0.0, pinch, t) *
               mix(1.0, smoothstep(0.0, pinch, 1.0 - t), clamp(uConverge, 0.0, 1.0));
  vec2 offset = kink(t, seed, span) * uJitter * ends;  // 3. изломы
  float angle = seed * TAU + (t * uTwist + uTime * uTwistSpeed) * TAU;
  float reach = mix(uSpreadNear, uSpread, pow(clamp(t, 0.0, 1.0), max(uSpreadCurve, 0.01)));
  offset += vec2(cos(angle), sin(angle)) * reach * radial;  // 2. веер
  return axis + n1 * offset.x + n2 * offset.y;
}
```

Три слоя складываются: **ось** (единственная часть, знающая направление каста),
**веер** (постоянное смещение нити в перпендикулярной плоскости, раскрывающееся
от `spreadNear` у руки до `spread` у цели и катящееся вокруг оси через `twist`) и
**изломы**.

Изломы — октавы value-шума с **линейной** интерполяцией, и это осознанный выбор,
прописанный в комментарии: `smoothstep` скруглил бы углы, а углы — единственная
причина, по которой это читается как молния, а не как виляющая труба.

```glsl
float vnoise(float x, float seed) {
  float i = floor(x); float f = x - i;
  return mix(hash11(i + seed), hash11(i + 1.0 + seed), f) * 2.0 - 1.0;
}
```

Цикл октав — фиксированные 5 итераций с гейтом `step(float(i), uOctaves - 1.0)`:
динамическая граница цикла не портируема, а пять MAD дешевле ветвления.

Локальный базис берётся через Грама–Шмидта, а не «как есть»: ось наклонена вниз
от руки, поэтому `uSide` только приблизительно перпендикулярен ей.

```glsl
vec3 n1 = uSide - dir * dot(uSide, dir);
n1 = length(n1) > 1e-4 ? normalize(n1) : normalize(cross(dir, vec3(0.0, 1.0, 0.0)));
vec3 n2 = normalize(cross(dir, n1));
```

Лента разворачивается к камере векторным произведением локального тангенса
(конечная разность по `boltPoint`) и вектора на камеру — поэтому молния держит
видимую толщину с любого ракурса, ни разу не будучи screen-space линией. И
финальный штрих: `vec4 mv = viewMatrix * vec4(here + binormal * side * halfWidth, 1.0)` —
**мимо `modelMatrix`**, потому что группа абилки и так единичная, а
проход через модельную матрицу только пригласил бы её дрейфовать.

Два клока управляют мерцанием: `restrike` защёлкивает каждую нить на новую форму
N раз в секунду (`floor(uTime * uRestrike)` в сид), а `crawl` непрерывно
скользит изломами между защёлкиваниями.

### 5.2 Труба луча — `(t, a)`

`createBeamTubeGeometry(nodes = 96, sides = 26)` — та же идея на измерение
богаче: `t` вдоль ствола, `a` вокруг него. Шов дублируется, чтобы `a` доходил до
ровно 1.0 и угловой шум не показывал стык.

Труба, а не ribbon, потому что колонна такой толщины обязана **иметь сечение**:
силуэт должен правильно выгибаться при облёте, дальняя стенка — складываться
через ближнюю, ударные диски — облегать её.

Ключ к виду — как взвешены три прохода одной и той же трубы:

* **halo** — самый широкий, только rim-член;
* **sheath** — rim-взвешенный, читается как *полый*, ярче всего на кромке
  силуэта;
* **core** — узкий и взвешен **наоборот**: ярче там, где луч зрения идёт вдоль
  ствола и путь сквозь трубу длиннее.

Rim снаружи, axis внутри, обе грани аддитивные — это дешёвый интеграл по объёму,
и именно инверсия делает середину сплошным стержнем света, а не освещённой
трубой. Обе взвешивающие функции строятся из одного числа, посчитанного в
вершинном шейдере:

```glsl
vFacing = abs(dot(normalize(cameraPosition - here), nrm)); // 1 вдоль ствола, 0 на силуэте
```

`beamRadius(t)` и `beamAxis(t, n1, n2)` — это вся геометрия луча; катушки и
ударные диски позиционируются **против тех же двух функций**, поэтому при
перетаскивании `radius` или `flare` все пять слоёв остаются сваренными.
Ничего не кэшируется — функции вычисляются на вершину, на кадр.

Ударные диски (`createBeamRingGeometry`) — инстансированный аннулус, фаза
которого `fract(aRing / uRingCount + uTime * uRingSpeed)`. Весь поезд дисков —
чистая функция часов, на CPU нет никакой очереди.

Шум луча намеренно **гладкий**, вытянутый вдоль потока и ползущий вниз по
стволу — «луч, который изламывается, это молния». Storm Lance и Nova Beam делят
цветовую семью специально: их разделяет только характер движения.

### 5.3 Клетка ловушки — четыре роли на одной ленте

`SnareMaterial` — самое плотное место проекта. Одна инстансированная лента
рисует всю ловушку; **роль** нити решается в вершинном шейдере сравнением
индекса инстанса с четырьмя живыми счётчиками, и роль выбирает параметрический
путь:

```glsl
vec3 pathAt(float role, float f, float seed, float t) {
  if (role < 0.5) { /* leash  — провисающая линия от руки к движущемуся концу */ }
  if (role < 1.5) { /* column — закручивающийся подъём из центра              */ }
  if (role < 2.5) { /* tendril — меандр наружу, veer как per-filament константа */ }
  /* rim — дуга, бегущая по границе, перепрыгивающая её в середине пролёта     */
}
```

Дальше все смещения живут в базисе, снятом **конечной разностью** по этому пути,
что и позволяет одной функции изломов обслуживать и вертикальный столб, и нить,
ползущую плашмя по полу. Два наземных роля гасят вертикальную компоненту
смещения (`offset.y *= 0.3`) и клампятся выше пола: свободный `y` закапывает
половину каждого щупальца, и эффект читается как пунктир.

Вырожденность базиса на вертикальном столбе обработана явно:

```glsl
vec3 upRef = abs(tangent.y) > 0.9 ? vec3(1.0, 0.0, 0.0) : vec3(0.0, 1.0, 0.0);
```

Обнуление счётчика роли снимает её целиком — так поводок исчезает ровно на том
кадре, когда кольцо берёт управление. Две draw call покрывают все четыре роли,
сколько бы нитей ни было в воздухе.

### 5.4 Кольцо дальности

`ZoneIndicator` рисует кольцо дальности у кастера на той же ленте, согнутой в
окружность: `(t, side)` на входе, мировая позиция на выходе. Причина
прагматичная: квад, достаточный для 20 м дальности, был бы 40 м в поперечнике и
шейдил бы полэкрана отбрасываемых фрагментов ради одной тонкой линии.

### 5.5 Анизотропный масштаб в `GlacierMaterial`

Отдельная деталь, которую легко упустить: лезвие короны масштабируется как
`(radius, height, radius)` — анизотропно, поэтому инстанс-матрица завалила бы
каждую нормаль в сторону длинной оси. В вершинном шейдере честно применяется
inverse-transpose, тот же, что использует сам three:

```glsl
mat3 im = mat3(instanceMatrix);
vec3 invScale = vec3(dot(im[0], im[0]), dot(im[1], im[1]), dot(im[2], im[2]));
objectNormal = im * (objectNormal / invScale);
objectAxis   = im * (objectAxis   / invScale);
```

## 6. Процедурная геометрия на CPU

`assets/ProceduralGeometry.js` — то, что нельзя отдать вершинному шейдеру,
потому что оно должно двигать силуэт тени и нормали.

**Кристалл** (`createCrystalGeometry`) — сужающаяся, огранённая, слегка изогнутая
призма в единичном пространстве: базовое кольцо на `y = 0`, вершина на `y = 1`.
Инстанс поэтому независимо масштабирует след и высоту, а `local.y` читается прямо
как «насколько высоко по кристаллу я нахожусь» — на этом держится полосование
инея в `IceMaterial`. Углы граней джиттерятся один раз и переиспользуются всеми
кольцами, иначе грани закрутились бы винтом. Неровность растёт к вершине: у
земли кристалл почти круглый, у обломанного конца — рваный. Геометрия
неиндексированная + `computeVertexNormals()` → чёткие грани.

**Астероид** (`createAsteroidGeometry`) — три слоя поверх икосферы:

1. *fbm-комья* — крупная форма (значный шум на CPU: GLSL-библиотека здесь не
   годится, вершинный шейдер не сдвинет силуэт тени);
2. *плоскостные срезы* — камень режется несколькими случайными полупространствами,
   и всё, что снаружи плоскости, **проецируется на неё**. Это даёт настоящие
   плоские грани, сходящиеся острыми рёбрами, — по комментарию, «самая большая
   разница между этим и просто смещённой сферой»;
3. *кратеры* — чаши с насыпным валом, пробиваемые сквозь всё это.

Смещение — чистая функция **направления** вершины, и это тонкий момент: именно
поэтому неиндексированная геометрия (нужная для плоских граней) не расходится по
швам — продублированные вершины делят направление и двигаются одинаково.

## 7. Материалы: восемь разных подходов

| Материал | База | Ключевая идея |
|---|---|---|
| `IceMaterial` | патч `MeshStandardMaterial` | тени и IBL сцены остаются настоящими; стилизация инжектится сверху |
| `GlacierMaterial` | сырой `ShaderMaterial` | дисперсионный fresnel, свет по телу лезвия, фронт заморозки, шаттер |
| `LightningMaterial` | сырой | весь путь болта в вершинном шейдере, два прохода |
| `BeamMaterial` | сырой, 6 режимов через `#define BEAM_PASS` | три радиуса трубы + катушки + диски + орб |
| `SnareMaterial` | сырой, 2 прохода | четыре параметрических роли на одной ленте |
| `MeteorMaterial` | патч `MeshStandardMaterial` | лавовые швы как нулевой переход fbm, в **локальном** пространстве |
| `VolumetricFireMaterial` | сырой рейтмарчер | четырёхслойное поле плотности, планковское излучение |
| `FrostFieldMaterial` | сырой, 2 материала | лист льда на полу + завеса холодного воздуха на границе |

### 7.1 Лёд: почему патч, а не замена

`IceMaterial` патчит `MeshStandardMaterial` через `onBeforeCompile` (композиция
патчей — через `utils/shaderPatch.js`, чтобы никто никого не затёр молча).
Кристаллы благодаря этому отбрасывают и принимают настоящие тени сцены и
подхватывают HDR-пробу. Стилизация — пять членов:

* **толщинный тинт** — грань, видимая в лоб, имеет самый длинный путь сквозь
  кристалл, поэтому темнеет к `colorDeep`; скользящие кромки остаются бледными.
  Именно этот член заставляет поле читаться как тело, в которое можно
  *заглянуть*, а не как синий пластик.
* **внутренние трещины** — ridged-шум в **мировом** пространстве, чтобы плоскости
  разлома держали фиксированный физический размер: щиколоточный осколок и
  трёхметровый шип выглядят выломанными из одного ледника.
* **перистый иней и рима** — fbm в **локальном** пространстве (0..1 вверх по
  кристаллу), чтобы прожилки следовали собственной оси шипа, как бы его ни
  масштабировали и ни наклоняли.
* **блики** — жёстко пороговое высокочастотное поле, скользящее в мировом
  пространстве, смещённое к скользящим углам.
* **вспышка рождения** — per-instance атрибут `aBirth`, который абилка гонит от 1
  к 0 за `birthFade`.

Отдельного упоминания заслуживает мягкий потолок:

```glsl
glow /= 1.0 + glow * 0.22;
```

Члены независимы и все пикуют на скользящем угле, поэтому складываются; без
Рейнхардовского отката грань на силуэте суммируется за 10 и кристалл читается как
белое пятно с размазанным блумом. Асимптота `1/0.22 ≈ 4.5` — слайдеры продолжают
кусаться в верхней части диапазона.

Три `InstancedMesh` делят один материал: три, а не один, потому что различаются
**грани**, а не пропорции; per-instance масштаб такого разнообразия силуэтов не
купит, а три draw call — дешёвая цена.

### 7.2 Ледяная корона: намеренно противоположная обработка

`GlacierMaterial` написан от противного к `IceMaterial`, и в комментарии это
проговорено прямо: две морозные абилки на одной панели должны различаться раньше,
чем это сделает силуэт, а перекраски недостаточно. Поэтому там, где Frost Lance
молочный, рассеянный и тем глубже тонированный, чем толще тело, лезвия короны —
почти пустое стекло, вытянутое на кромках:

* **дисперсионная кромка** — fresnel считается **трижды**, с тремя чуть разными
  экспонентами, и результаты гонят R, G и B независимо. Каждая грань берёт своё
  место в расщеплении (`hash13(floor(N * 7.0) + vSeed * 5.0)`), поэтому соседние
  грани не бахромятся одинаково;
* **свет, проведённый по телу лезвия** — эмиссия собирается на гранях, вдоль
  которых идёт ось (`1.0 - abs(dot(N, vAxis))`), и лезет к вершине через
  `pow(h, uTipBias)`;
* **штриховка вместо инея** — ridged-шум, растянутый вдоль собственной оси;
* **настоящее отражение** — один equirect-сэмпл HDR-пробы плюс узкая солнечная
  доля, причём направление солнца берётся из тех же `settings.environment`, что
  освещают сцену.

И две подписи, ради которых это отдельный материал, а не смена палитры:

```glsl
float ragged = snoise01(vLocal * 5.0 + vSeed * 7.0) * uFrontRough;
float front  = vGrow * (1.0 + uFrontRough) - ragged;
if (h > front) discard;                       // фронт кристаллизации
```

`aGrow` — per-instance высота, и всё выше неё дискардится по шумному срезу:
лезвие **кристаллизуется вверх** из земли, а не выезжает из дырки. Шероховатость
прибавляется обратно перед вычитанием шума — так полностью выросшее лезвие
(`aGrow = 1`) никогда не врезается само в себя.

Шаттер — порог `aShatter` против per-fragment «идентификатора куска», собранного
наполовину из вороного в собственном пространстве лезвия, наполовину из хэша
нормали плоской грани. Первая половина ломает тело на куски, игнорирующие
геометрию; вторая уносит **целые плоские грани** — то, что на самом деле
происходит с кристаллом.

### 7.3 Метеор: то же поле, другое пространство

`MeteorMaterial` рисует лавовые швы как нулевой переход fbm:
`1 - smoothstep(0, width, abs(fbm))` даёт тонкий ветвящийся лист там, где шум
меняет знак, — именно так выглядит настоящий разлом, меандрирующий и вилчатый, а
не как царапина.

И здесь важен контраст с льдом: поле сэмплируется в **локальном** пространстве,
поэтому трещины приварены к камню и кувыркаются вместе с ним. Лёд специально
делает наоборот (мировое пространство), потому что там задача обратная — чтобы
целое поле выглядело выломанным из одного блока. Одна и та же техника, два
осознанно разных пространства сэмплирования.

`uCharge` гонится от 0 к 1, пока метеор идёт к цели: швы расширяются и ярчеют,
камень заметно разогревается на подлёте, и взрыв становится тем, что ты *видел
приближающимся*.

### 7.4 Объёмный огонь: единственный настоящий рейтмарчер

`VolumetricFireMaterial` (833 строки, 573 из них GLSL) — самый тяжёлый шейдер
проекта, перенесённый из предыдущей инкарнации песочницы. Меш, на который он
надет, — **не пламя**, а лишь камера-ориентированный proxy-hull вокруг траектории
(`RibbonGeometry` с опцией `frame`, которая пишет `aCenter` и `aTangent`). Каждый
фрагмент восстанавливает локальный базис кривой, пускает луч от камеры сквозь
себя и интегрирует эмиссию и поглощение.

Поле строится в четыре слоя, от грубого к мелкому — «в том порядке, в каком глаз
читает настоящий огненный шар»:

1. **силуэт** — капсула вокруг траектории, каплевидная в сечении (плавучесть
   тянет её вверх), радиус модулируется одной очень низкочастотной октавой шума.
   Это не декор: очертания огненного шара доминируются лопастями метрового
   масштаба, а многооктавная турбулентность на частоте деталей пламени может лишь
   покусывать край капсулы;
2. **вихревой сворот** — вращение доменa шума в плоскости (поток, вертикаль)
   бегущей волной складывает поле само на себя. «Обычный fbm, сколько октав ни
   бери, делает облака; он никогда не делает завитки»;
3. **турбулентность** — 5 прогрессивно домен-варпнутых октав с поворотом между
   октавами (убивает выравнивание по решётке), каждая дрейфует вверх быстрее
   предыдущей;
4. **shred** — эрозия слабая на оси и яростная на бахроме: сердцевина остаётся
   плотной, край распадается на пряди.

Шейдинг температурный, а не градиентный. Цвет — планковский излучатель
(пьесовая аппроксимация Таннера Хелланда), мощность — `pow(kelvin/Tcore,
uEmissionCurve)` (Стефан–Больцман). Красная бахрома → оранжевое тело → белое ядро
и колоссальный динамический диапазон между ними выпадают из физики, а не
подбираются руками.

В комментарии зафиксирован урок, который «стоил многих рендеров»: излучаемая
мощность идёт как высокая степень температуры, поэтому контраст того, что гонит
температуру, умножается на экране в несколько раз. Направьте этот усилитель на
турбулентное поле — и он ляжет на его линии уровня (вложенные замкнутые петли), и
пламя отрендерится как полированный агат в контурных линиях. Лечится только
затуплением температурного поля — отсюда три отдельных решения: heat-поле только
из грубых октав, скромный `uHeatFollow` и выполаживание с возрастом.

Марш — 72 шага с адаптивным страйдом: пустое пространство прочёсывается шагом
до 2.2×, при первом попадании страйд мгновенно падает до 1. Блендинг —
premultiplied «over», а не аддитив, как у остального VFX: настоящее пламя и
излучает, и **загораживает**. Марш обрезается по depth prepass, поэтому объём
корректно закрывается землёй и персонажем.

## 8. GPU-частицы

`particles/ParticleSystem.js` — инстансированные квады, вся симуляция в шейдере.
CPU пишет **только spawn-данные** и заливает только те слоты, которые изменились.

Ключевые решения:

* **аналитическое затухание** вместо интегрирования — точное и не зависящее от
  частоты кадров:
  ```glsl
  float k = max(uDrag, 1e-3);
  float travel = (1.0 - exp(-k * age)) / k;
  vec3 pos = aStart + vel * travel + 0.5 * uGravity * age * age;
  ```
* **кольцевой буфер**: эмиссия сверх ёмкости перерабатывает старые слоты, а не
  аллоцирует;
* **мёртвые частицы выбрасываются за пределы клип-объёма** (`gl_Position =
  vec4(2.0, 2.0, 2.0, 1.0)`), и GPU отбрасывает весь треугольник до растеризации;
* **шесть процедурных силуэтов** через `#define SHAPE` — SOFT, SMOKE, STREAK,
  LEAF, CHIP, RING. Спрайтов нет ни одного: CHIP, например, это
  `r = 0.62 + 0.24*sin(ang*5 + seed*30) + 0.1*sin(ang*9 - seed*11)`;
* **soft particles** через полуразрешающий depth prepass — общий хелпер
  `softFade()` в `shaders/lib/common.glsl.js`;
* **`RateEmitter`** копит дробный остаток: `rate * dt` округлился бы в ноль на
  высоком FPS и выстрелил пачкой на низком. Плюс жёсткий потолок 240 частиц за
  кадр, чтобы залипание не вывалило тысячи разом.

Системы создаются лениво по имени и **разделяются между всеми инстансами
абилки** — двадцать кастов подряд переиспользуют один буфер. Наборы по абилкам:
Frost Lance — mist/shards/glitter; Storm Lance — sparks/motes/smoke/debris; Nova
Beam — те же четыре, причём motes работают дважды (втягивание в орб при зарядке и
снос с колонны при стрельбе); Glacial Crown — mist/shards/glitter/**snow**, и snow
здесь подпись абилки: ледяная пыль спавнится *над* короной и падает сквозь неё.
Всё остальное в проекте бросается вверх, и медленное падение внутри кольца — это
то, что говорит «воздух над этим замерзает, а не горит».

Мелкая, но важная деталь: искры сыплются **из нескольких точек вдоль болта за
кадр** (`SPARK_BATCHES = 6`), потому что луч осыпается по всей длине, а единая
точка происхождения превращает каждую пачку в салют.

## 9. Пайплайн рендера

Каждый кадр:

1. **depth prepass** — непрозрачный мир (`LAYER.WORLD`) в полуразрешающий буфер
   с упакованной глубиной. Каждый VFX-шейдер сэмплирует его для мягких
   пересечений. Кристаллы сидят на `WORLD` — поэтому туман и блёстки мягко
   гаснут об них;
2. **distortion pass** — меши слоя `DISTORTION` пишут screen-space UV-смещения во
   второй полуразрешающий буфер. **В текущей сборке в него никто не пишет** —
   проход оставлен как крючок для будущей рефракции и стоит один half-res clear
   за кадр (честно указано в разделе «известные шероховатости»);
3. **композер** — scene → refraction warp → bloom → tone map (ACES) → grade.

`GradeShader` сворачивает в один ресэмпл хроматическую аберрацию,
lift/gain/contrast/saturation/temperature, виньетку, зерно плёнки и вспышку удара.

Тени: один directional light, ортокамера которого каждый кадр рецентрируется на
персонажа и подгоняется под коробку 52 м при 4096² (≈1.3 см/тексель).
`three/addons` CSM был попробован и удалён — он заменяет чанк
`lights_fragment_begin` **глобально**, и любой материал, явно не
зарегистрированный в нём, молча теряет всё направленное освещение.

Контактные тени — настоящий рендер: глубина персонажа снимается снизу в цель
256², дважды блюрится и проецируется на пол.

`shadowMap.autoUpdate = false`, а `needsUpdate = true` выставляется ровно один
раз за кадр — сцена рендерится несколько раз (prepass, distortion, контактные
тени, основной проход), и автообновление перестраивало бы карты теней на каждый
из них.

## 10. Прицеливание: два индикатора, один контроллер

`AimController` пускает луч в плоскость земли **каждый кадр**, а не только на
move, — поэтому облёт камерой при взведённом касте водит индикатор под
неподвижным курсором. И работает на **реальном** времени, а не на масштабируемой
дельте симуляции: пауза замораживает эффекты, а не UI.

Стрелка — **одно SDF-поле в метрах**. `vUv` перемапливается так, что `p.y` —
расстояние от кастера вдоль линии, `p.x` — поперечное смещение, оба в мировых
метрах. Каждый контрол в `settings.aim` поэтому реальный размер: древко остаётся
0.42 м шириной, будь каст 3 м или 15 м.

Силуэт — скруглённое объединение бокса (древко) и **точного треугольного SDF от
iq** (наконечник); дешёвое пересечение полуплоскостей оставляет видимые артефакты
на таком пологом клине. Из одного дистанционного поля выводятся: обводка,
rim-взвешенная внутренняя заливка, шевроны (фаза скошена на `|x|`, что превращает
плоские полосы в стрелки, указывающие туда же, куда каст), морозный шум,
вороные-плиты, кольцо у ног, дуга максимальной дальности, шестилучевая розетка на
точке удара и sweep-out при взведении.

Круг far cast построен на тех же двух идеях — метры и никаких текстур. Полоса
границы намеренно самая тяжёлая метка на экране и разбита относительно
номинального радиуса через `boundaryBias`, а не отцентрована на нём: игрок судит
о том, *где кончается эффект*, поэтому внешняя губа полосы должна оставаться
честной. Круг **выскакивает за свой радиус и оседает обратно** — растущий линейно
читается как элемент UI, перелетающий — как действие кастера.

## 12. Производительность: что сделано и почему

* **Пулинг по типам.** Абилки, декали, всплески и частицы. Двенадцать кастов
  подряд построят максимум **четыре** инстанса абилки и на этом перестанут
  аллоцировать (`MAX_CONCURRENT = 4`, общий на все типы — смешивание абилок
  снимает самый старый каст независимо от его стихии).
* **Draw calls** (по README): всё ледяное поле — 3 вызова независимо от числа
  кристаллов (потолок 288); весь болт — **2** вызова независимо от числа нитей
  (потолок 24 нити × 72 сэмпла); вся ловушка — 2 вызова плюс один на поле; весь
  луч — **6**. Ничего из формы не трогает CPU, поэтому `strands`, `tendrils`,
  `coils` почти бесплатны. Замеры: 32 вызова в покое, ~69 со стоящим ледяным
  полем, ~186 на четырёх одновременных кастах.
* **Шесть динамических точечных источников создаются на старте и паркуются на
  нулевой интенсивности**, а не добавляются и убираются: изменение числа
  источников меняет ключ кэша программы освещения и заставляет three
  перекомпилировать *каждый* материал. `LightPool.acquire()` возвращает `null`
  при исчерпании, и все обращения к хэндлу защищены.
* **Общие uniform-боксы по идентичности.** `core/FrameUniforms.js` раздаёт одни и
  те же `{ value }` объекты всем материалам: одна запись за кадр обновляет
  десятки VFX-материалов.
* **Кэш цветов.** Редактор хранит цвета строками `#rrggbb`, шейдерам нужны
  `Color` каждый кадр; `utils/color.js` мемоизирует по строке и мутирует
  uniform-значения из кэша.
* `renderer.compileAsync()` на старте — первый каст не заикается на компиляции.
* Pixel ratio ограничен 1.75; depth и distortion буферы — половинного разрешения.
* `gl.info.autoReset = false` + ручной `reset()` — счётчики HUD считают ровно
  один кадр.

## 15. Расхождения и шероховатости

**Документация:**

* README заявляет пять абилок, в коде шесть; у Glacial Crown нет ни описания, ни
  строки в таблице управления, ни папки в списке папок редактора.
* «938 живых слайдеров» → фактически 1137.
* Раздел «Editor and presets» перечисляет 13 папок и не упоминает шестую абилку.

**Код (мелочи, ни одна не ломает сборку):**

* `GlacierAbility` вызывает `createGlacierMaterial(environment)`, а сигнатура —
  `createGlacierMaterial()` без параметров. Аргумент молча игнорируется; в
  отличие от `createIceMaterial(environment)`, которому окружение нужно для
  `registerShadowCasterWithPatch`. Glacier — сырой `ShaderMaterial`, ему это
  действительно не нужно, но вызов вводит в заблуждение.
* `ridged(vec3 p, int unusedOctaves)` в общей библиотеке шума принимает число
  октав и не использует его — цикл всегда 4 итерации. Все вызовы передают `4`,
  так что расхождения в поведении нет.
* Число треугольников кристалла расходится между README и комментариями в коде.
  README говорит «60 треугольников», а `_syncGeometry` в `IceAbility` и
  `GlacierAbility`, как и шапка `ProceduralGeometry.js`, — «108». Я построил
  геометрию и посчитал: **60** (4 кольцевых пояса × 6 граней × 2 + 6
  треугольников вершины + 6 донышка = 60; 180 вершин, геометрия
  неиндексированная). Права README, комментарии в коде завышают вдвое. На
  аргумент это не влияет — 60 треугольников тем более дёшево перестроить.

**Честно задокументированные авторами острые углы:**

* Кристаллы рисуются с `transparent: true` и `depthWrite: true` — правильный
  компромисс для почти непрозрачного льда, но на низком `ice.opacity` артефакты
  сортировки между перекрывающимися шипами становятся видны.
* Фронт извержения — прямая линия на плоском полу. Оба допущения зашиты: земля —
  единственная плоскость на `y = 0`, и луч прицеливания бьёт в неё же. Far cast
  наследует это дважды (круг на кваде при `y = 0`, щупальца и дуги против той же
  плоскости) — ни то, ни другое не ляжет на ступеньку.
* Distortion-проход работает вхолостую.
* И круг прицела, и поле ловушки аддитивные, то есть **осветляют** пол, а не
  затеняют его. На светлом полу границе понадобился бы неаддитивный проход снизу.

## 16. Что отсюда стоит забрать

1. **«Никаких размерностей на CPU».** Это не оптимизация, это архитектурное
   решение, которое покупает редактор, работающий на паузе. Записи хранят броски
   костей и таймстемпы; всё остальное разрешается каждый кадр.
2. **Parameter-space геометрия.** Один буфер `(t, side)` или `(t, a)` обслуживает
   болт любой длины, формы и толщины. Форма становится живым слайдером, а не
   константой, требующей рестарта, и CPU не участвует вообще.
3. **Три прохода одной трубы с инвертированными весами.** Rim снаружи, axis
   внутри, обе грани складываются — дешёвый интеграл по объёму, дающий сплошной
   стержень света.
4. **Domain warp вместо `atan()`.** Урок, зафиксированный дважды (наземные ожоги
   болта и поле ловушки): сэмплирование шума по `atan(y, x)` выдаёт всем радиусам
   вдоль пеленга одно значение и рисует прямые спицы из центра — салют, а не
   ожог. Сэмплировать надо в плоскости и варпить лукап.
5. **Мягкий потолок Рейнхарда на сумме эмиссивных членов.** Независимые члены,
   пикующие на одном скользящем угле, складываются в белое пятно; `x/(1+kx)`
   оставляет всё ниже ~1 нетронутым и сохраняет полезный ход слайдеров.
6. **Линейный value-шум там, где нужны углы.** Единственная разница между
   молнией и виляющей трубой.
7. **Температура вместо палитры для огня.** И предупреждение про то, что `T^n`
   умножает контраст того, что гонит температуру, и укладывает его на линии
   уровня турбулентного поля.
8. **Пул света с нулевой интенсивностью.** Добавление/удаление источника
   перекомпилирует все материалы — классическая причина фриза при спавне VFX.

## Как запустить

```bash
git clone https://github.com/achrefelouafi/LinearAbiltyCastingThreeJS.git
cd LinearAbiltyCastingThreeJS
npm install
npm run dev     # http://127.0.0.1:5173
```

Управление: `Q E R F V X` (или `1`–`6`) — взвести абилку, движение мыши — водить
стрелку/круг, ЛКМ — каст, `Esc`/ПКМ — отмена, ПКМ+перетаскивание — облёт камерой,
колесо — зум, `G` — редактор, `P` — пауза (редактор продолжает применяться),
`C` — очистить эффекты, `H` — спрятать панель управления.
